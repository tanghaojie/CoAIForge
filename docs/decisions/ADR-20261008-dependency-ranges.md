# 兼容依赖范围与可复现构建

用户明确要求去掉 pnpm <13：pnpm 只声明 >=10.26.0 下界，未来大版本没有经过验证不能作为设置上限的依据；实际验证矩阵与允许安装的范围分别记录。0.2.1 携带这一调整和此前 Node 20 / Nest 11 的兼容实现。

用户要求长期迭代不固定运行时、包管理器与直接依赖版本，并明确环境版本无需特别新，兼容即可。Node 和 pnpm 只通过 engines 声明经验证的兼容范围；推荐环境用于便捷选版，不强制最新补丁或自动下载特定包管理器。直接依赖默认使用 ^ 范围。锁文件保留已验证的依赖图；日常/CI/发布安装使用冻结锁文件，更新依赖通过显式升级后重新验证和提交锁文件。

最新版本需同时满足依赖 peer 与运行时约束；无法兼容时记录最新兼容版本和限制，不强行关闭 peer/类型检查。2026-10-08 用户进一步确认当前源码收敛为 Node ^22.13.0 || >=24.0.0，推荐 Node 22，保留所有现有依赖、锁文件与 pnpm >=10.26.0。不为支持早期 Node 22 降级 ESLint/Vite，也不将范围写成会包含 Node 23 的 >=22.13.0。此前为 Node 20 选择的 Nest 11 与 @types/node 20 继续保留；不以强行 override 或忽略 engines 实现兼容。pnpm 下界由 allowBuilds 首次支持版本约束，保留安装脚本权限与 minimumReleaseAge。已公开的 0.2.1 保持发布时的 Node 20 范围，本轮不发布。跨大版本升级通过独立审查实施。当前策略与验证入口见[运行时与依赖升级策略](../design/dependency-lifecycle.md)。
