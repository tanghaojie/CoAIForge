# 去掉 pnpm 上限并发布 0.2.1

## 目标、授权与设计依据

用户明确要求去掉 pnpm <13 并发布 npm 包。依据[依赖策略](../../design/dependency-lifecycle.md)和[发布流程](../../guides/npm-release.md)，版本从公开 latest 0.2.0 升为尚未占用的 0.2.1。Node 20 与 Nest 11 调整已经在此前提交验证，本轮不增加应用行为或前端验收范围。起始工作区、暂存区为空，归档 NOT_DUE，npm 发布身份已确认。

## 实施步骤和退出条件

- [x] 确认发布授权、现有版本，准备设计与协作记录
- [x] 去掉现行声明中的上限，更新 0.2.1 版本与文档，运行维护仓库门禁
- [ ] 提交已验证发布候选源码，让最终 tarball 引用真实来源 SHA
- [ ] 验证实际 tarball 的三种工程，用相同产物发布 npm
- [ ] 核实 registry 的版本、engines 与 integrity，验证公开包三种创建
- [ ] 更新最终证据、归档、索引与提交

## 实际结果、偏差、遗留与提交

Node 20.19.0 / pnpm 10.26.0 下维护仓库冻结且严格 peer 安装、格式、Lint、29 项测试、文档、模块及归档 CI 门禁均通过。发布源码通过允许检查，接下来提交候选并验证最终快照。未来 pnpm 大版本没有运行证据，开放 engines 不等于宣称已经验证；前端人工验收计划仍保留。来源与实际产物将在发布验证记录中登记。
